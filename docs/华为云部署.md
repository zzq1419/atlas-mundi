### 为什么不能当静态网站托管

华为云从 **2022-01-01** 起（华北-北京一/四、华东-上海一/二、华南-广州）**禁止用默认域名做静态网站托管**。
用桶域名或 `*.obs-website.*` 在浏览器访问网页时，平台强制加 `Content-Disposition: attachment`，
浏览器会**下载**而不是渲染。

实测三种绕法全部无效：

| 尝试 | 结果 |
| --- | --- |
| 对象设 `Content-Type: text/html; charset=utf-8` | 头正确，`attachment` 仍在 |
| 带浏览器 `Accept: text/html,...` + Chrome UA | 无效 |
| 用 OBS 原生签名显式发 `Content-Disposition: inline` | **`Cache-Control` 生效了，`inline` 被平台覆盖** |

第三条最有说服力：同一请求里 `Cache-Control` 被正确保存，说明签名与请求构造没问题，
是平台侧硬性改写。唯一官方解法是绑定**已备案的自定义域名**，备案周期不适合本项目。

### 最终方案：双源分离

| 内容 | 托管位置 | 原因 |
| --- | --- | --- |
| `index.html`、`data/*.json`、`geo/*.geojson` | GitHub Pages | 同域 `fetch` 不需要 CORS |
| `assets/` 图片与音频 | **华为云 OBS 上海一** | `<img>`/`<audio>` 子资源不受 `Content-Disposition` 影响；国内节点快 5~12 倍 |

实测速度（同一文件）：

| 文件 | OBS 上海 | GitHub Pages | 倍数 |
| --- | --- | --- | --- |
| `assets/cn/L01.webp` 75 KB | **0.31 s** | 3.87 s | 12× |
| `assets/fr/L01.webp` 91 KB | **0.25 s** | 1.26 s | 5× |
| `assets/cn/audio/zh.mp3` 36 KB | **0.25 s** | 2.80 s | 11× |

前端 `setAsset()` 做**双源回退**：优先 OBS，失败自动退回仓库相对路径。

### 上传工具

```bash
export HUAWEI_AK=xxx HUAWEI_SK=xxx
python scripts/upload_obs.py --bucket atlas-mundi-1419 --region cn-east-3 --dry-run
python scripts/upload_obs.py --bucket atlas-mundi-1419 --region cn-east-3
```

两个必须知道的 SDK 坑：

1. **`putContent(headers={...})` 传 dict 会被静默忽略**，必须传 `PutObjectHeader(contentType=...)`。
   后果：`.webp` 存成 `binary/octet-stream`（浏览器当文件下载），**返回码仍是 200**，只有打开页面才发现。
2. `PutObjectHeader.allowedAttr` 里**没有** `cacheControl`，传了会报 `unexpected keyword argument`。
   要设 `Cache-Control` 只能走原生签名 PUT。

## 2. FunctionGraph 函数工作流 ✅ 已完成（云端测试返回 3 条）

已备好代码与函数包：`scripts/fg_search/`（`handler.py` + `search.json`）、`scripts/fg_search.zip`（6.7 KB）。

### 这个函数做什么

把前端同一套检索算法（中文 2-gram + BM25 + 停用词 + 双阈值）封成 Serverless 接口。
**与前端结果逐条比对过，14 条查询 100% 一致（含分数）**，所以不是两套实现，是一套逻辑的两种部署形态。

两种形态的意义：页面用本地检索（快、可离线），外部客户端（小程序、命令行、别的系统）走 API。

### 部署步骤

| 步 | 操作 | 关键点 |
| --- | --- | --- |
| 1 | 控制台搜索「**函数工作流 FunctionGraph**」→ 创建函数 | 选「**空白函数**」，不要用模板 |
| 2 | 函数类型选「**事件函数**」 | 事件函数才能挂 API 网关触发器 |
| 3 | 函数名称 `atlas-search`，运行时「**Python 3.9**」（或 3.10） | 3.9/3.10 都行，只用标准库 |
| 4 | 代码上传方式选「**本地 ZIP 文件**」，上传 `scripts/fg_search.zip` | 不要在线粘贴，`search.json` 13KB 粘不动 |
| 5 | **函数入口填 `handler.handler`** | ⚠️ 最容易漏。默认可能是 `index.handler`，不改会报「找不到模块」 |
| 6 | 高级设置：内存 128 MB、超时 10 s | 128MB 足够，函数包里只有 20KB 数据 |
| 7 | 创建后点「**测试**」，测试事件填 `{"q": "长城"}` | 应返回 3 条结果，首条「长城是什么时候建的？」 |

### 🔴 部署时实测踩到的三个报错

**① `failed to find module 'index'(No module named 'index')`**

华为云新建函数的**默认入口是 `index.handler`**，而我们的包是 `handler.py`，
所以第一次测试必然报这个 ImportError。两种改法任选其一：

| 改法 | 操作 |
| --- | --- |
| A（推荐） | 函数详情 → 「设置」/「基本信息」→ **函数入口** 改为 `handler.handler` |
| B（零配置） | 改传 `scripts/fg_index_compat.zip`（包内文件名为 `index.py`，正好对上默认入口） |

注意入口格式是 `文件名.函数名`，**用点号不是斜杠**。

**② `JSON格式不正确，请重新输入`（配置测试事件时）**

那个弹窗左边有「事件模板」，选中后编辑器里会预填 `{"key": "value"}` 这样的占位结构。
如果直接把自己的 JSON 追加在后面，就变成两段拼接。正确做法：**先 Ctrl+A 全选删除，再填**。

事件名称填 `test`（只能英文数字下划线），JSON 填在「事件内容」编辑区 —— 两个框很容易搞混。

**③ 委托（Agency）不用选**

委托是给函数访问其他云服务用的（读 OBS、发短信、写 LTS）。本函数只做纯计算
（读包内 `search.json` → 算 BM25 → 返回），不碰任何云服务，留空即可。

## 3. API 网关 ⚠️ 已评估并主动放弃（APIC 默认报价 4 万元）

> **结论先行**：这一项**不影响评分**。函数已经在 FunctionGraph 里跑通（云端测试返回
> `count=3`），「云平台使用」这一项已经计数。API 网关只是给函数一个公网 URL，
> **不追求公网调用的话可以直接跳过**。

### 🔴 陷阱：触发器类型默认是 APIC，实例要 4 万元

函数详情页点「创建触发器」，**触发器类型的默认值是 `API Connect (APIC)`**，而 APIC
需要先创建实例 —— 点「创建实例」跳转后默认是**包年专业版，报价约 4 万元/年**。

这不是我们能用的东西。这一屏的正确反应是：**关掉，不要点「创建实例」**。

FunctionGraph 支持两种 API 类触发器，区别如下：

| 触发器类型 | 需要什么 | 费用 | 是否可用 |
| --- | --- | --- | --- |
| **API Connect（APIC）** | 必须创建 APIC 实例 | 专享实例包年，万元级 | ❌ 不要用 |
| **API 网关（APIG）** | 需要 API 分组 + 实例 | 基础版有 100 万调用/月长期免费额度 | ✅ 若下拉里有这一项才选 |

### 如果要尝试（可选）

| 步 | 操作 | 关键点 |
| --- | --- | --- |
| 1 | 「触发器类型」下拉 → 换选 **API 网关触发器**（不是 APIC） | 下拉里没有这一项就放弃，不必强求 |
| 2 | API 分组：新建，名 `atlas_api` | 只能用字母数字下划线 |
| 3 | 实例：**只选基础版/共享版** | ⚠️ 看到「专业版」「专享版」立刻退出，那按小时计费（约 12.88 元/小时） |
| 4 | **安全认证选「None / 不认证」** | 选 IAM 后每次调用都要签名，浏览器和脚本都访问不了 |
| 5 | 方法勾 GET 与 POST | 两个都勾，方便测试 |
| 6 | 保存，复制调用 URL | 形如 `https://xxx.apig.cn-east-3.huaweicloud.com/...` |

拿到 URL 后跑验证：

```bash
python scripts/call_fg.py --url "https://你的地址" --q "长城"
python scripts/call_fg.py --url "https://你的地址" --full
```

`--full` 跑 7 条查询并逐条比对**期望结果表**（与本地一致才算通过）。

### 若 API 网关实在走不通：函数的公网替代方案

不挂网关也能对外提供调用，两条零成本路径：

1. **FunctionGraph 的「测试」功能**：控制台里填事件 JSON 直接调用，返回结果可截图，
   足够作为「函数在云端真实运行」的举证。
2. **OBS 触发**（可选）：往桶里传一个 JSON，函数读取后把结果写回桶。全程无公网 URL，
   但确实是「函数被云端事件驱动执行」。

我们的函数逻辑与前端 100% 一致（14 条查询逐条比对含分数），所以即便不做公网 API，
检索能力在页面上已经是可用的、可演示的。
