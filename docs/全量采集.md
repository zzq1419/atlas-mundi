## 1. 阶段一：ISO → Wikidata QID

```bash
python scripts/resolve_ids.py                 # 全量，约 8~15 分钟
python scripts/resolve_ids.py --limit 20      # 先试 20 个
python scripts/resolve_ids.py --report        # 随时看进度 / 差哪些
```

产物 `data/_ids.json`：`{"JP": {"qid": "Q17", ...}, "_langs": {"Q5287": {"c1": "ja"}}}`

**校验方式**：候选实体的 P297（ISO 3166-1 alpha-2）必须等于目标 ISO，否则换英文名再搜。
仍失败的会进 `data/_ids_unresolved.json`，可以手工补：

```bash
python scripts/resolve_ids.py --set XK=Q1246
```

> 为什么不用 SPARQL：部分代理下它会返回 200 + 空结果，极难排查。这里走
> `wbsearchentities` + `wbgetentities`（批量取 claims），一次请求覆盖 5~6 个候选。

## 2. 阶段二：采集正文 / 图片 / 语言 / 坐标

python scripts/collect_all.py --stage collect --limit 5    # 先跑 5 个看质量

## 2b. 阶段二点五：地标图（模型点名 + Commons 实搜）

`collect.py` 只拿得到 Wikidata 的 **P18 代表图**，每国一张，而且经常不是地标：
日本拿到"2003 年 5 月日本卫星影像"，美国拿到 UNOCHA 的定位地图。这不能当详情页主图。

三国那套好看的地标图是人工往 `data/landmarks.json` 写检索词换来的。223 国不可能手写，
但也不能靠关键词瞎猜。分两级：

```bash
python scripts/build_landmarks.py --limit 5   # 模型给每国列 6 处地标（zh / kw / must）
python scripts/fill_images.py --all           # 按 kw 去 Commons 搜，文件名必须含 must
```

`fill_images.py` 的筛选分三档，只有前一档全军覆没才启用下一档：

| 档 | 宽度 | 宽高比 | 谁可以走这档 |
| --- | --- | --- | --- |
| strict | ≥ 900px | ≤ 2.2 | 编辑挑过的图（P18 / 维基首图）+ 关键词命中 |
| relaxed | ≥ 800px | ≤ 3.2 | 只给编辑挑过的图 |
| loose | ≥ 640px | ≤ 4.5 | 只给编辑挑过的图（最后兜底） |

关键词命中**永远不会放宽**：放宽立刻引来"合影照"——实测搜 `Great Pyramids of Giza`
第一名是 Forever is Now 艺术展那件巨型金属手，金字塔在远处小得像三颗牙。
文件名含 `exhibition / installation / sculpture / replica / painting / stamp …`
的直接毙掉。

为什么改成三档：吉萨金字塔群的 P18 是一张 2.4:1 的三塔全景，被原来的 2.2 硬线判成
"全景长条"直接淘汰 —— 埃及那一栏就没有金字塔。宁可给一张略宽的全景，
也不要给用户一个空框。

**模型编造的地标会被自动淘汰**（Commons 搜不到）。实测日本 6 处里成功 5 处
（富士山 / 伏见稻荷 / 晴空塔 / 广岛原爆慰灵碑 / 姬路城）。

### 补缺口

跑完会写 `data/_image_gaps.json`（哪个国家、哪处地标、为什么没拿到）。补的时候：

```bash
python scripts/fill_images.py --gaps      # 只重试有缺口的国家
```

`fill_images.py` 是**增量**的：已经抓好并落盘的图会按 `kw` 认出来直接沿用，
不会因为补一处地标就把整国 5 张图重下一遍（也就不会换掉已经人工确认过的那几张）。

### 批量跑完怎么抽查

每张图都记了 `pick_tier`（strict / relaxed / loose）。放宽才拿到的那批最可能出问题，
先看它们：

```bash
python -c "import json,glob;[print(f, [i['caption_zh'] for i in json.load(open(f,encoding='utf-8'))['landmark_images'] if i.get('pick_tier')!='strict']) for f in glob.glob('data/*.json')]"
```

223 国跑完，`fill_images` 阶段大约 2 小时（每国 6 处地标 × 3 路候选 + 3 次 imageinfo）。

### 一國留几张：不按人口猜

```bash
python scripts/fill_images.py --plan     # 先看每国的清单条数、人口、准备留几张
```

上限 = `min(模型给的清单条数, 5)`，不按人口折算。

第一版写的是"人口不到 100 万封顶 3 张"，被冰岛当场打脸：冰岛 37 万人，
蓝湖 / 黄金瀑布 / 间歇泉 / 辛格维利尔 / 杰古沙龙 / 大教堂，六处都是真名胜，
凭什么只给 3 张？反过来卢森堡 65 万人确实只有两处可写。人口和文化资源不相关。

"小国少几张"现在是**筛出来的结果**，不是预设的规则：

| 国家 | 人口 | 清单 | 实际留图 |
| --- | --- | --- | --- |
| 冰岛 | 36 万 | 6 | **5**（蓝湖/黄金瀑布/间歇泉/辛格维利尔/杰古沙龙） |
| 不丹 | 76 万 | 6 | 3（虎穴寺/普纳卡宗/帕罗宗） |
| 基里巴斯 | 12 万 | 6 | **2**（菲尼克斯珊瑚礁/贝蒂奥港） |

要精确控制某一国，在 `data/landmarks.json` 加：

```json
{"caps": {"FJ": 5, "KI": 2}}
```

### 图源分四级，可信度决定优先级

| 级别 | 来源 | 权重 | 说明 |
| --- | --- | --- | --- |
| 1 | 中文 Wikidata P18 / 中文维基首图 | +2.5 / +2.0 | 编辑挑过 |
| 2 | **条目正文配图** | +1.4 | 编辑为了讲清条目放进去的图 |
| 3 | 英文维基首图 | +1.0 | 解析条目名，带 must + 无括号两个守卫 |
| 4 | Commons 全文搜索 | 0 | 覆盖最广，噪声最大 |

**第 2 级是这轮的关键。** 小国在 Commons 全文搜索里只有办公楼、机场、黑白图版 ——
连着加三轮黑名单词（office → council → medical center），每加一条就冒出下一个词。
根子不在规则不够，在**图源不对**：全文搜索不区分"这图是不是在讲这个地方"。
换成条目正文配图后，基里巴斯从"5 张里 3 张废图"降到"2 张都是真风景"。

### 废图闸门：分类比文件名可靠

`iiprop` 不返回分类，得单独 `prop=categories` 查。能拦掉的东西：

| 判据 | 拦的是什么 | 实例 |
| --- | --- | --- |
| 分类含 satellite / sentinel / copernicus | 卫星影像 | `Tarawa, Kiribati ESA22224800.jpeg` |
| 分类含 geophysical data / seamount | 海底地形 | `3dPerspective wSeamounts NoRefs.jpg` |
| 分类含 historical image / archival | 档案老照片 | 1967 年 Smithsonian 的黑白鸟类图版 |
| 说明含 airport / warehouse / office building | 普通设施 | `Airport building Abaiang Atoll Airport` |
| 文件名以 location / map 开头 | 定位图 | `LocationBanaba.PNG` |
| 原图 < 25 KB | 纯色块示意图 | 5 KB 的定位图 |
| 套图序号 ≥ 20 | 细部特写 | `Punakha Dzong, Bhutan 26.jpg`（屋檐金饰） |

### 说清楚天花板

这套规则**保证不了"画面上就是这处地标"**。基里巴斯最后还剩两张要人手删的：
`Battle Tarawa.jpg`（二战照片）、`Banaba door stop.jpg`（岛屿形状的门挡工艺品）。
每张图都记着 `pick_tier` 和 `source`，批量跑完按这两个字段抽查是唯一靠谱的收口方式：

```bash
python -c "import json,glob;[print(f, [i['caption_zh']+':'+i.get('source','') for i in json.load(open(f,encoding='utf-8'))['landmark_images'] if i.get('source')=='commons_search']) for f in glob.glob('data/*.json')]"
```

### 识别"配错条目"的编辑图

Wikidata 的 P18 也可能配错：中文"帕罗宗"条目的 P18 是 **Drugyel Dzong**（另一座宗堡）。
所以编辑图也要过一道专名校验 —— 文件名里连 `must` 都没有的，扣 3 分（等于取消它的
优先权），让真正命中专名的实搜图赢。实测不丹帕罗宗因此从 Drugyel Dzong 换成了
`Rinpung Dzong, Bhutan 01.jpg`。

### 同一组套图的序号偏好

Commons 常见 `Punakha Dzong, Bhutan 01.jpg … 26.jpg` 这种一次传几十张的系列。
01 通常是正面全景，越往后越可能是细部特写——实测第 26 张是屋檐一角的金饰，
尺寸、比例、专名全合规，但画面上根本没有宗堡。所以小号加分、大号减分。

### 还加了一路：英文维基首图

小国的宗堡、环礁、村落基本只有英文条目，中文维基一片空白，原来只能掉到 Commons
全文搜索，拿回地图和书页扫描件。现在中文那几路凑不够 2 个候选时，会去英文维基
解析条目名再取首图，并且要求**条目标题含 must**、**标题不带括号消歧义** ——
否则斐济的 "Garden of the Sleeping Giant" 会解析到美国康涅狄格的 "Sleeping Giant"。

它排在关键词搜索之后，只当兜底：解析条目名这一步本身就会跑偏。


产物写回 `landmark_images`，带 `caption_zh`（中文图注）—— 采集阶段那批图没有图注，
详情页会显示空白。

## 8. 已知限制（别期待和三国一模一样）

1. **图片是自动挑的**。三国用的是人工挑选的地标（埃菲尔铁塔、长城），
   全量走 P18 代表图 / 正文配图，可能挑到市政厅、街景，甚至被过滤成 0 张。
   想提升只有两条路：给重点国家补 `data/landmarks.json` 关键词，或人工换图。
2. **摘要长度不均**。小国维基条目只有一两句，LLM 精炼后会低于 300 字。
3. **民俗成文是模型稿**。有 evidence 可核，但没有人工稿的质感；
   三国的人工稿不要被覆盖（`compose` 只在 `custom_text` 为空时写，或显式 `--force`）。
4. **语音语种覆盖有限**。Edge TTS 约 70 个语种，冷门语种跳过。
5. **球面国界**只有三国是精细几何，其余国家点开时才按需画（`geo/c*.json`）。

## 9. 常见报错

**`UnicodeEncodeError: 'gbk' codec can't encode character '\u2717'`**

2026-10-28 那次"五国全失败"就是它：脚本在 cp936 终端里打印 `✓/✗` 直接抛异常，
看起来像采集失败，其实连抓取都没开始。现在所有脚本都做了两件事：
非 ASCII 符号换成 `[ok]`/`[x]`，并且 `sys.stdout.reconfigure(errors="replace")` 兜底。

**`SSL handshake timed out` / 连接失败，但浏览器能打开维基**

Python 的 urllib **不读 Windows 系统代理**（Clash/v2rayN 改的是注册表），只认
`HTTP_PROXY / HTTPS_PROXY`。`scripts/netcheck.py` 会自动探测：环境变量 → 注册表 →
常见端口（7897/7890/10809…），每个候选都真抓一次维基才算数。所有入口都接了；
要手工指定就加 `--proxy http://127.0.0.1:7897`。

**重复 ISO 覆盖**：Natural Earth 里 AU 有三个要素（Australia / Indian Ocean Ter. /
Ashmore and Cartier），后写的会把澳大利亚覆盖成"澳屬印度洋領地"（人口 2387）。
`build_countries.py` / `build_labels.py` 现在同 ISO 只留人口最多的那个。


| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 四个域名全 0 可达 | 代理没开 / 规则没覆盖 wikimedia | 开代理，或 `--proxy` 指定 |
| `没有 XX 的 QID 映射` | `_ids.json` 里缺这条 | `resolve_ids.py --set XX=Qxxx` |
| `HTTP 429` | 请求太密 | 加大 `--sleep`，脚本本身有退避重试 |
| 语音全跳过 | 语言码解析不到 / 无音色 | `speech_all.py --voices <code>` 查 |
| `upload 失败 401` | AK/SK 过期 | 换子用户密钥 |
