## 二、已修（build 2026-11-24-T）

### 1. 搜索框回车没拦输入法（真 bug，中文用户必踩）

`#q` 的 `keydown` 里只有 `e.key === 'Enter'` 就直接 `preventDefault()` 然后选第一条结果。打拼音时，**回车是"确认这个候选词"**，于是"新喀"还没选完词就被提交搜索了。

指南 `ime-safe-enter-submit`：

> "Single-line `<input>` fields with their own `Enter` handling, such as search and find bars … receive the same IME-confirming `Enter` keydown … with `isComposing` set to `true`."

改法（`index.html` 约 6741 行）：在 `preventDefault()` **之前**拦

```js
if (e.isComposing || e.keyCode === 229) return;
```

`keyCode === 229` 是 Safari 的兜底（它把 `compositionend` 派发在 `keydown` 之前，`isComposing` 已被清成 false；WebKit bug 165004）。检查顺序很关键：先 `return` 再 `preventDefault`，否则会把输入法正在组的那次提交一起拦掉。

实测：组词状态回车 → 不跳；普通回车 → 正常打开详情。

### 2. 工具按钮在手机上对读屏"没有名字"

抽屉里的按钮只放图标，名字全靠 `.tl` 悬停气泡；而横屏窄高度那条媒体查询里写着 `.tool-btn .tl{display:none}`（为了塞下 34px 的小按钮）。实测手机横屏 844×390：

```
btn-china  34×34  aria-label=null  innerText=""  .tl display=none
```

读屏只会念"按钮，已按下"，没有名字。指南 `natural-interactions` 要求每个控件有可编程名称与可见焦点。

改法：把 `.tl` 的文字镜像到 `aria-label`，并用 `MutationObserver` 跟随改写（自转/昼夜这类状态文字会变成"开启自转"，`aria-label` 一起跟进）。实测：初始 `常驻中国上空`，关自转后变 `开启自转`，再点回 `暂停自转`。

> 遗留小瑕疵：这些是 `aria-pressed` 开关，而 `.tl` 是"动作名"（暂停自转/开启自转）。指南的建议是**固定名称 + pressed 状态**，不要用会变的动作名。现在是"动作名 + pressed"并存，读屏会念"暂停自转，已按下"。要彻底干净得给 14 个按钮各起一个固定短名（国境线 / 经纬线 / 昼夜 …），需要你点头再改。

### 3. `prefers-reduced-motion` 只关了一半

原来只有：

```css
@media (prefers-reduced-motion:reduce){ *{transition:none!important} }
```

关掉了 transition，但 `@keyframes` 全部照跑（shimmer 骨架、gspin、skelPulse、sugpop、kitIn、tsShimmer…），3D 地球也照转。

不能直接写 `animation:none` —— 有几处靠 `forwards` / `both` 把终态留在元素上（`tpIn` 的提示气泡从 `opacity:0` 开始、`kitIn` 的面板），取消动画会永远停在 `opacity:0`。指南 `motion` 的分支是"改参数"而不是"删动画"，所以改成零延迟、跑一次、1 ms 跑完：

```css
*,*::before,*::after{animation-duration:1ms!important;animation-delay:0s!important;
  animation-iteration-count:1!important}
```

实测（`reduced_motion=reduce`）：`animation-duration: 0.001s`、`iteration-count: 1`、面板 `opacity:1/visible`（没被冻住）。

> 地球自转属于"持续 5 秒以上的运动"，WCAG 2.2.2 要求有暂停手段 —— `#btn-spin` 已经满足，没有额外改。

### 4. 附带：结果行箭头本来不亮

`.sr-country-row:hover .sr-arrow{...}` 这条选择器早就匹配不到了（结果行改名成了 `.sr-item`）。补一条 `.sr-item:hover .sr-arrow`，和整行底色同一帧到位。

## 三、待办（按优先级，都还没动）

### P0 · 搜索结果行键盘不可达

`sr-item` 是 `<div>` + `click` 监听（3 处创建点：约 5186 / 5884 / 6450 行）。键盘用户只能 Tab 到搜索框，然后按回车开第一条，**没法用 Tab / 方向键在列表里选**。指南 `natural-interactions`：

> "Use `<button>` for actions and `<a>` with an `href` for navigation."

改法：`el('div','sr-item')` → `el('button','sr-item')`，CSS 补 `width:100%;text-align:left;font:inherit;background:none;border:0`。风险：三处创建点 + `.sr-item` 的 hover/点击逻辑要跟着验一遍；改完 Focus 环会出现在每一行（这是应该的）。

### P1 · 触控目标偏小（手机横屏为主场景）

实测（844×390，`pointer: coarse`）：

| 控件 | 尺寸 | 指南建议 |
|---|---|---|
| `.tool-btn`（抽屉 14 颗） | 34×34 | 触屏 ≥ 44×44 |
| `.sr-sug-more`（换一批） | 26×26 | 同上 |
| `.search-clear`（清空叉） | 高 20 | 同上 |
| `.kit-x`（关面板） | 32×32 | 同上 |

指南 `form-factor-adaptation`：

> "Make every control at least 24×24 CSS pixels (WCAG 2.5.8), and at least 44×44 on touch screens … To keep small icons visually compact, extend their hit area with a pseudo-element."

抽屉那排 4 颗按钮在 200px 面板里，4×44 + 3×6 = 194 已经贴着内宽上限，**真改尺寸会换行/撑高面板**。可行的是伪元素扩命中区（`.tool-btn::after{inset:-3px}`，间隙 6px 刚好不重叠 → 40px），或者只给手机上改成 3 列 × 44px。需要你先定方向。

### P1 · hover 样式没有 `(hover: hover)` 守卫

61 条 `:hover` 规则，0 条媒体查询守卫。桌面没问题；触摸设备上点一下会留下"粘住的悬停态"（Chrome/Android 的做法是点击即赋 `:hover`，直到下一次点到别处），删掉的图层按钮底色会一直亮着像"还按着"。

> 说明：Playwright 的手机模拟里 `:hover` 根本不成立（`row.matches(':hover')` 为 false，鼠标事件被当成触摸），所以这条**没法在模拟器里复现**，是按行为规范判断的。

指南 `natural-interactions` 给的写法是把 hover 收进媒体查询：

```css
@media (hover: hover) { .tool-btn:hover { … } }
```

改造成本：61 条里真正会粘住的是抽屉按钮、结果行、色签、答题选项这十几条，可以只包这些。

顺带一个 UX 真空：手机横屏下 `.tl` 是 `display:none`，**触摸用户完全看不到这 14 颗图标按钮是干什么的** —— 没有悬停提示、也没有长按提示。现在只解决了读屏（`aria-label`），看得见的说明还缺。要么手机上给按钮补一行小字，要么加长按/点一下的提示。

### P2 · `el.innerHTML = ''` × 25

确定性扫描 25 处（清空列表/面板都用 `innerHTML=''`）。指南 `js`：

> "Assigning empty innerHTML invokes the HTML parser and fails under Trusted Types; use element.replaceChildren() instead."

现在没有 XSS 风险（内容都是自己模板生成的），但这是 Trusted Types 上线的硬门槛，且 `replaceChildren()` 语义更清楚。机械替换，风险低，可批量做。

### P2 · 打开搜索一次性渲染 236 行 → 64 ms 长任务

实测桌面打开搜索结果出现 1 个 64 ms 长任务（超过 50 ms 的 INP 红线）。列表是 236 个国家行 + 建议区，共 3024 个节点一次性建出来。

可选项：给 `.sr-item` 上 `content-visibility:auto; contain-intrinsic-size: 58px`（滚动容器外的行跳过渲染）；或先渲染 30 行、滚动再补。前者一行 CSS，但会影响 Ctrl+F 查找和文本选择的行为，需要取舍。

### P3 · 细节

- 没有 `<search>` 地标 / `role="search"`，读屏的"跳到搜索"没有落点。
- `#tools-body` 用 `role="dialog" aria-modal="false"`：非模态抽屉其实用 `role="dialog"` 就够，`aria-modal="false"` 是噪音（不是错）。
- 滚动条双写：`::-webkit-scrollbar*`（多处）+ `scrollbar-width/color`（5+2 处）。Chrome 121+ 已支持标准属性，webkit 那套现在是给旧 Chrome / Safari 兜底，可以只保留标准写法 + 一条降级。

## 四、已经做对的（不用改）

- `:root{color-scheme:dark}`：深色场景下 native 控件（滚动条、输入框、日期选择器）跟着走深色。
- 全局 `:focus-visible{outline:2px solid rgba(148,182,224,.78);outline-offset:3px}`，且 `outline:none` 的地方都补了替代焦点样式。
- 图片：`decoding="async"` + `loading="lazy"` + 详情大图 `fetchpriority="high"` + 骨架占位（避免 CLS）。
- 事件：`touchstart` / `wheel` 用 `{passive:true}`，`overscroll-behavior:contain` 防止滚到底带飞整页。
- `will-change` 只给当前可见的几十个图层，注释里写清了为什么不全量挂。
- 自转有暂停按钮（WCAG 2.2.2）。

---

## 五、不建议现在做的

- **把抽屉/详情面板换成原生 `<dialog>` + `popover`**：指南推荐，但这两个面板的定位、遮罩、动画、Esc 分层退出都是手写且已经调好的，换成 top-layer 要重做 `@starting-style` + `transition-behavior: allow-discrete`，收益（无障碍语义）远小于风险。
- **容器查询（container queries）**：本项目响应式靠视口宽度 + 固定像素面板，容器查询能省几条媒体查询，但没有实际收益。
- **`text-wrap: balance`**：卡片标题多为短中文，收益很小。
